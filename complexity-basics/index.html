Time and Space Complexity for Beginners

Before you learn any data structure, you need a way to measure how fast and how memory-hungry your code is. That's what Big-O notation does. This page explains the essentials in plain language — no proofs, no heavy math.

Why learn this first? Every topic in the DSA Roadmap references time and space complexity. If you skip this, you won't be able to tell whether your solution is good enough. Read this page once, then revisit it whenever you need a refresher.

What Is Big-O Notation?

Big-O describes the upper bound of how an algorithm's runtime (or memory use) grows as the input size n increases. It answers: "If I double my input, roughly how much longer will this take?"

We care about the growth rate, not the exact number of operations. Constants and lower-order terms are dropped because they don't matter at scale.

The 5 Complexities You Must Know

O(1) — Constant Time

What it means: The operation takes the same amount of time regardless of input size.

Example: Accessing an array element by index (arr[5]). Whether the array has 10 elements or 10 million, getting the 5th element takes one step.

When you see it: Hash map lookups (average case), pushing/popping from a stack, checking if a number is even.

O(log n) — Logarithmic Time

What it means: Each step cuts the remaining work in half. Doubling the input adds only one extra step.

Example: Binary search. Searching in a sorted array of 1,000 elements takes about 10 steps (log₂ 1000 ≈ 10). Searching in 1,000,000 elements takes about 20 steps.

When you see it: Binary search, balanced BST operations, divide-and-conquer algorithms that discard half the data each time.

O(n) — Linear Time

What it means: The work grows proportionally to the input. Double the input, double the time.

Example: A single loop through an array to find the maximum value. If the array has n elements, you look at each one exactly once.

When you see it: Any algorithm that visits every element once — linear search, computing a sum, traversing a linked list.

O(n log n) — Linearithmic Time

What it means: Slightly worse than linear but much better than quadratic. Common in efficient sorting algorithms.

Example: Merge sort and quick sort (average case). They divide the array in half (log n levels) and do O(n) work at each level.

When you see it: Efficient sorting, some divide-and-conquer problems, problems where "sort first, then solve" is the approach.

O(n²) — Quadratic Time

What it means: The work grows with the square of the input. Double the input, quadruple the time.

Example: A nested loop where the outer loop runs n times and the inner loop also runs n times — like checking every pair in an array (brute-force Two Sum).

When you see it: Bubble sort, selection sort, brute-force pair comparisons. If n is larger than about 10,000, O(n²) is usually too slow.

At n = 1,000,000, O(n²) performs a trillion operations. That would take minutes or hours on most computers. O(n log n) does about 20 million — easily under a second.

Space Complexity

Space complexity measures how much extra memory your algorithm uses (beyond the input itself). The same Big-O notation applies:

  • O(1) space: You use a fixed number of variables (e.g., swapping two numbers with a temp variable).
  • O(n) space: You create a new array or hash map proportional to the input size.
  • O(n) stack space: Recursive calls can use O(n) space on the call stack if recursion depth is proportional to n.

When a problem says "solve it in O(1) extra space", it means don't create new data structures that grow with the input — modify the input in-place or use a constant number of variables.

How to Analyse Your Own Code

Follow these steps when looking at your solution:

  1. Count the loops: A single loop over n elements = O(n). A nested loop = O(n²). Three nested loops = O(n³).
  2. Look for halving: If the loop cuts the data in half each time (like binary search), it's O(log n).
  3. Drop constants: O(2n) simplifies to O(n). O(n/2) simplifies to O(n). The constant doesn't change the growth rate.
  4. Take the dominant term: O(n² + n) simplifies to O(n²) because n² grows much faster than n.
  5. Check recursive calls: If a function calls itself twice (like naive Fibonacci), it's often O(2ⁿ). If it calls itself once and halves the input, it's O(log n).

Quick rule of thumb: Most competitive programming judges allow about 10⁸ operations per second. If n = 10⁵ and your algorithm is O(n²), that's 10¹⁰ operations — it will time out. You need O(n log n) or better.

Common Mistakes Beginners Make

  • Confusing Big-O with exact time: O(n) doesn't mean your code runs in exactly n milliseconds. It describes the growth pattern, not the absolute speed.
  • Ignoring space complexity: An O(n) time solution that also uses O(n) extra space may not be ideal. Many interviewers ask for O(1) space.
  • Forgetting best, worst, and average cases: Quick sort is O(n log n) on average but O(n²) in the worst case. When someone says "quick sort is O(n log n)", they usually mean the average case.
  • Over-optimising too early: Get a correct O(n²) solution first, understand why it works, then optimise. A working brute-force beats a broken clever approach.
